# CB Model Projections — Master Site Redesign Prompt

## Mission
Redesign **CB Model Projections** into a premium, fast, mobile-first college football analytics product that feels credible enough for serious bettors and approachable enough for a first-time visitor. The site is a research interface, not a sportsbook. It must make the model's projection, market comparison, data quality, validation state, and supporting research easy to inspect without implying that a large model/market gap is automatically a bet.

## Non-negotiable technical constraints
- Keep the site static and deployable on GitHub Pages.
- Use semantic HTML, CSS, and vanilla JavaScript only. No framework or build step.
- Keep weekly content data-driven through `data/config.json`, `data/projections.csv`, `data/results.csv`, and `data/research.json`.
- Preserve all existing data-loading and grading logic unless a change is explicitly required for the redesign.
- Preserve dark/light theme, responsive desktop table + mobile cards, search/filter/sort, bookmarks, sharing, CSV export, record tracker, research tabs, methodology, glossary, support, and responsible-gambling disclaimer.
- Never present HOLD projections as released wagers.
- Keep model output, market reference, model/market gap, data quality, and validation state visually distinct.

## Brand and visual direction
The product name is **CB Model Projections**.

Visual tone: modern college-football command center + professional quantitative dashboard. Athletic without looking like a sportsbook clone. Use a deep midnight/navy base, electric lime as the primary model color, cyan/blue for market/reference data, amber for caution/HOLD states, and restrained green/red only for graded outcomes. Light mode should feel like premium sports analytics, not a generic white admin panel.

Design traits:
- Bold condensed-feeling scoreboard typography using system fonts only.
- Strong hierarchy and large numeric readouts.
- Subtle field-grid / yard-line motifs rather than literal football graphics.
- Layered panels, thin borders, controlled glow, crisp spacing, and strong contrast.
- Rounded corners should feel intentional and tighter than a generic SaaS dashboard.
- Motion should be subtle and respect `prefers-reduced-motion`.
- Avoid visual clutter, casino styling, flashing odds, neon overload, or language such as “lock,” “hammer,” or “guaranteed.”

## Information architecture
Use a sticky navigation with these destinations:
1. Home / Command Center
2. Projections
3. Record
4. Research
5. Methodology
6. Glossary
7. Support
8. About

### Home / Command Center
Above the fold, visitors should immediately understand:
- what the site is,
- when it was last updated,
- how many games are loaded,
- whether spread/totals validation is LIVE or HOLD,
- current model version,
- that the site is research-only.

Use a two-column hero on desktop and stacked layout on mobile. The left side carries the brand statement and primary actions. The right side is a compact “Model Command Center” with validation/readiness cards. Under it, show four slate summary metrics such as average projected total, average favorite margin, highest win probability, and market-reference coverage.

### Projections
This is the core product area. Make it the visual priority after the hero.

Controls:
- Team search
- Week filter
- Conference filter
- Date filter
- Sort control
- Reset
- Export filtered CSV

Desktop table columns:
- Game / kickoff / conference
- Model score
- Model spread
- Market spread
- Spread gap
- Model total
- Market total
- Win probability
- Model-implied moneyline
- Data quality / signal
- Save / share actions

Mobile must render each game as a compact but information-rich card rather than a squeezed table.

Visual language:
- Model values = lime / primary model color.
- Market values = cyan / reference color.
- Large model/market differences may receive stronger emphasis, but never language that implies a released bet.
- Data quality and signal strength should be visible at a glance.
- Market source, observation time, and execution-verification context should remain discoverable.
- Saved/starred games should sort to the top while preserving the selected secondary sort.

### Record Tracker
Make the record section feel like a transparent audit page, not a promotional win-rate graphic.
- ATS record
- Straight-up record
- Number of graded projections
- ATS cumulative trend chart
- Weekly record table
- Conference breakdown

Clearly state that this grades model projections, not wagers placed.

### Research Hub
Research should feel like an evidence center. Keep category tabs generated by `data/research.json` and support availability, weather, market, efficiency, tempo, schedule, roster, and situational categories. Each category should show its status, summary, and item cards with compact tags.

### Methodology
Explain the model pipeline in plain English using six steps:
1. Build team strength
2. Adjust for opponents
3. Project matchup
4. Add game context
5. Compare with market
6. Validate prospectively

Explicitly explain why a large model/market gap is not automatically a wager.

### Glossary
Keep fast definitions for spread, ATS, moneyline, total, push, win probability, model/market gap, and data quality.

### Support and About
Support should be tasteful and secondary. Make clear it is optional and that site content remains free. About should position the site as a transparent front end for model projections and research.

## Responsive behavior
- Design from mobile upward.
- Keep the sticky header usable on narrow screens.
- Avoid horizontal overflow outside intentionally scrollable data tables.
- Projection cards on mobile should surface the matchup, projected score, model vs market spread, spread gap, model vs market total, win probability, status, and save/share controls with minimal taps.
- Touch targets must be at least ~42px.

## Accessibility
- Maintain semantic landmarks and labels.
- Preserve skip link.
- Strong visible focus state.
- High color contrast in both themes.
- Do not rely on color alone to communicate status.
- Respect reduced motion.
- Charts need accessible labels and nearby textual summaries.

## Product principles
1. **Projection first, market second.** The model is independently generated and then compared to the market.
2. **Context is part of the model workflow.** Injuries, weather, travel, depth and market freshness belong beside the numbers.
3. **Readiness is visible.** Validation HOLD states are not hidden or softened.
4. **No false precision.** Use one decimal where appropriate and explain uncertainty.
5. **Fast weekly maintenance.** Routine weekly updates must come from data files, not manual page edits.
6. **Trust over hype.** The design should make the project look more rigorous, not more promotional.

## Definition of done
The redesign is complete when:
- the site has a coherent premium visual system in dark and light mode,
- all existing functional IDs and data hooks still work,
- projections are easy to scan on desktop and mobile,
- HOLD validation state is obvious,
- research and record sections look intentionally designed rather than appended,
- there are no broken filters, charts, bookmarks, deep links, exports, or data loads,
- GitHub Pages can deploy directly from the repository root with no build step,
- the responsible-gambling disclaimer remains visible,
- and weekly updates still require only data-file changes.
